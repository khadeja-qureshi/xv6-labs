Looking at the backtrace output, which function is called syscall?
-> usertrap called syscall.
What is the value of p->trapframe->a7 and what does that value represent?
->a7 = 0xf (15), represents SYS_open, from the init user program.
What was the previous mode that the CPU was in?
-> SPP = 0 → previous mode was User Mode

Write down the assembly instruction the kernel is panicing at. Which register corresponds to the variable num?
-> scause=0xd sepc=0x80001c7e stval=0x0
The assembly instruction causing the panic: lw a3,0(zero)
 The register corresponding to num: a3

Why does the kernel crash? Hint: look at figure 3-3 in the text; is address 0 mapped in the kernel address space? Is that confirmed by the value in scause above? 
-> the kernel executed a load from virtual address 0x0. Address 0 is not mapped in the kernel address space ,so a page-fault occurred (scause=0xd = load page fault; stval=0x0 shows the accessed address).

What is the name of the process that was running when the kernel paniced? What is its process id (pid)?
Process name: <p->init>
           PID: <p->1>
